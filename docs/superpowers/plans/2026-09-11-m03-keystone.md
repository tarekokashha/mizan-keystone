# M-03 KEYSTONE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A real LeRobot UR5e plugin with M-01 SENTINEL's safety kernel in front of it, proving that no action reaches the controller the kernel did not authorise.

**Architecture:** The driver carries no safety logic at all. All six defects in the kit's skeleton are removed rather than fixed, because the Shield already does that job and does it better. A deterministic fake of the RTDE interfaces makes the whole stack testable offline on any platform.

**Tech Stack:** Python 3.11, numpy, `ur_rtde` 1.6.5, `lerobot` 0.4.4, `mizan-sentinel` 0.1.0 installed from GitHub, pytest, hypothesis.

**Spec:** `docs/superpowers/specs/2026-09-11-m03-keystone-design.md`

## Global Constraints

- Python 3.11. Run through `.venv\Scripts\python.exe`. Tests: `python -m pytest -q`.
- Dependencies are exactly: `numpy>=1.26`, `ur_rtde>=1.6.5`, `lerobot==0.4.4`, `mizan-sentinel` (from GitHub). Test-only: `pytest>=8`, `hypothesis>=6.100`. Add nothing else without asking.
- **No em dashes in any prose**, including docstrings and comments. Kit convention.
- **Never write a real-robot number.** Every configuration value carries provenance in `{"datasheet", "declared"}`. Only a human who ran the arm may write `"measured"`. This mirrors M-01 and is not optional.
- **The follower contains no safety logic.** No clamps, no limits, no watchdogs, no force checks. If you find yourself adding one, stop: that is the Shield's job and duplicating it is how a driver becomes untrustworthy.
- Every module starts with `from __future__ import annotations`.
- Joint arrays are `float64`, shape `(6,)`. Positions rad, velocities rad/s, forces N, torques Nm, lengths m, time s.
- Commit at the end of every task, staging by explicit path. Never `git add -A`.

## Verified before this plan was written

Measured, not assumed:

- `ur_rtde` 1.6.5 has a Windows cp311 wheel and imports cleanly.
- **Every one of the 18 RTDE methods the kit's skeleton calls exists on the real interfaces.** `RTDEControlInterface` has 89 public methods, `RTDEReceiveInterface` 55, `DashboardClient` 32, and none of `servoJ`, `servoStop`, `stopScript`, `initPeriod`, `waitPeriod`, `getActualQ`, `getActualQd`, `getActualTCPPose`, `getActualTCPForce`, `getTimestamp`, `powerOn`, `brakeRelease`, `isInRemoteControl` is missing. The skeleton's API assumptions are sound; only its safety logic is not.
- `mizan-sentinel` 0.1.0 installs from GitHub and `Shield`, `SafetyKernel` import.
- Docker was not running when this plan was written. URSim work is gated accordingly.

### Task 1: Config, packaging, and the provenance rule

**Files:** Create `keystone/__init__.py`, `keystone/config.py`, `pyproject.toml`; Test `tests/test_config.py`

**Interfaces produced:** `UR5eConfig` (frozen dataclass) with `.sha256()`, `.to_dict()`, `.from_dict()`, `.replace()`, and `UR5eConfig.declared()`.

Fields: `ip`, `control_hz`, `servo_lookahead`, `servo_gain`, `gripper`, `cameras`, `id`, `provenance`, `measured_by`, `measured_on`.

**Note what is absent:** no `max_joint_velocity`, no `max_force_norm`. The skeleton had both. They are envelope values and they belong to SENTINEL's `Envelope`, not to a driver config. Duplicating them here would create two sources of truth for a safety limit, which is worse than having none.

- [ ] **Step 1: Write the failing test**

```python
def test_config_carries_no_safety_limits():
    # The skeleton had max_joint_velocity and max_force_norm here. They are
    # envelope values. Two sources of truth for a safety limit is worse than
    # one, and the Shield owns the envelope.
    cfg = UR5eConfig.declared()
    for forbidden in ("max_joint_velocity", "max_force_norm", "q_min", "q_max"):
        assert not hasattr(cfg, forbidden), (
            f"{forbidden} belongs to sentinel.Envelope, not to a driver config")


def test_measured_provenance_is_refused_without_a_named_human():
    d = UR5eConfig.declared().to_dict()
    d["provenance"]["control_hz"] = "measured"
    with pytest.raises(ValueError, match="measured"):
        UR5eConfig.from_dict(d)


def test_sha256_is_stable_and_sensitive():
    a = UR5eConfig.declared()
    assert a.sha256() == UR5eConfig.declared().sha256()
    assert a.replace(servo_gain=a.servo_gain + 1).sha256() != a.sha256()
```
